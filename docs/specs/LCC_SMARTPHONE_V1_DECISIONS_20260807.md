# Life Command Center スマホ版 v1 決定仕様・進行方針
保存日時: 2026-08-07 18:40 JST

## 0. この文書の位置づけ
この文書は、Life Command Center スマホ版 v1 について、2026-08-07 時点でオーナーとChatGPTの対話で決定した内容を固定する正本メモである。

# 1. スマホ版 v1 のスコープ

スマホ版 v1 は、いったん次の **2ページだけ** を完成させる。

1. ホーム
2. 保存リスト

予定、目標管理、ロードマップ、その他の機能拡張は、v1完成後に検討する。
風呂敷を広げず、まずこの2ページを完成品まで持っていく。

PC版にはすでにホームが存在する。
PC版とスマホ版は、同じデータ項目・意味・状態定義を共有してよいが、画面デザインやレイアウトは同じである必要はない。

### PC版とスマホ版で共通にするもの
- データ項目
- 項目名
- 意味
- 数値定義
- 状態定義

### 端末ごとに変えてよいもの
- レイアウト
- 優先順位
- 演出
- 操作導線
- 情報密度

# 2. ホームの目的

ホームの最重要目的は次の2つ。

1. **火を絶やさない**
2. **目標を忘れない**

スマホホームは、単なる情報一覧ではなく、
「自分の火を再点火し、目標を思い出し、行動へ接続する場所」とする。

---

# 3. ホームの7コマンド

PC版と同じ7コマンドをスマホ版にも置く。

1. 瞑想
2. イメージング
3. アファメーション
4. リーディング
5. ジャーナリング
6. エクササイズ
7. BTC1チャット

## 3.1 位置づけ
中核:
- アファメーション
- イメージング

目的:
- 目標を忘れない
- 自分が向かう方向を再接続する

それらを強化するミラクルメソッド:
- 瞑想
- ジャーナリング
- リーディング
- エクササイズ

現在の本線へ接続する実行導線:
- BTC1チャット

ホーム全体の流れは、

**目標を思い出す → 自分を整える → 本線を進める**

とする。

# 4. ホームのデザイン正本

現在の基準デザインは **RIOT NEON**。

デザインの本質:
- 黒背景
- マゼンタ / ピンク
- ライムイエロー
- シアン / ブルー
- 白
- ライブ会場
- ネオン
- グランジ / 手描き / ペイント感
- 反骨・覚醒・発進の熱量
- 多色がぶつかり合う一体感

単色に染めない。
「主軸色 + 対立色 + 補助色 + 白 + 黒」の多色構成を維持する。

### 7コマンド枠
- 7個の個別ボタンは、それぞれのネオン色と黒い内部を維持する。
- 7個全体を囲う大枠を設ける。
- 大枠は周囲と同じRIOT NEONの質感で馴染ませる。
- 外側にピンク / マゼンタ系の枠。
- その内側に太めの黄色ライン。
- 黄色ラインは機械的なベタ線ではなく、少し手描き・グランジ感を持たせる。
- 大枠は長方形ベース。
- 「後付けしたUI」に見えないことが必須。

# 5. 保存リストの目的

保存リストの本来の目的は、

**保存してきた大事なものを、スマホからすぐ見つけて読めるようにすること。**

これは「AIが整理した知識庫」であると同時に、
「過去の自分の脳へ直接アクセスする記憶庫」とする。

---

# 6. 保存リスト v1 必須機能

## 6.1 検索
検索対象:
- 整理タイトル
- オーナー原文
- 本文

表示モードに関係なく、検索は上記すべてを対象にする。

## 6.2 カテゴリ絞り込み
カテゴリ:
- 日記
- ルール
- 気付き
- その他

ALL表示も用意する。

## 6.3 表示方法切替
- カード表示
- 一覧表示

スマホで使いやすいことを優先する。
選択した表示方式は記憶する。

## 6.4 タイトル表示切替
1ボタンで以下を切り替える。

- 整理タイトル
- 俺の原文

### 整理タイトルモード
AIが整理した短いタイトルを表示。
一覧性を重視。

### 俺の原文モード
オーナーが実際に発言・指示した原文を表示。
本人の記憶・脳内検索との接続を重視。

原文が長い場合:
- 一覧では3〜4行程度まで表示
- タップで全文を読む

### 原文保存ルール
- 原文はAIが修正しない。
- 誤字、音声入力由来の表記も含め、原文として保持する。
- 整理タイトル / 整理版とは別フィールドにする。
- 原文を整理版で上書きしない。

## 6.5 並び替え
並び替え機能を設ける。

現時点で「新しい順」は候補として確定的。
その他のソートキーはまだ最終固定していないため、AIが勝手に追加確定しない。

## 6.6 詳細表示
保存項目をタップすると本文を読める。

v1では「探す・開く・読む」を中心にする。
大規模な編集機能はスコープ外。

## 6.7 表示状態の記憶
少なくとも以下を記憶可能にする。
- カード / 一覧
- 整理タイトル / 俺の原文

その他の状態記憶は実装時に必要性を監査する。

## 6.8 同期状態
表示候補:
- 最終同期時刻
- 手動更新
- 同期失敗時の再試行

保存内容の正本と表示画面がズレているか判断できること。

## 6.9 大量データ対応
保存数が増えても、
- 探せる
- 絞れる
- 並べ替えられる
- すぐ開ける

ことを守る。

一覧表示時に本文をすべて一括ロードするのではなく、
必要な項目の詳細を後から読む方式を優先する。

# 7. 保存データの正本思想

基本思想:
- 原本 / Markdown等の保存データが正本
- Life Command Center は閲覧・検索・操作の表示面
- JSON等のインデックスは補助用途

ダッシュボード側の表示データが、無断で別の正本にならないようにする。

BTC関連データは、Life OS側の一般保存リストと混ぜるかどうかを別途監査する。
以前の設計ではBTCは別扱いの思想があるため、v1実装時に勝手に統合しない。

# 9. 保存リストのデザイン正本

RIOT NEONホームと同じ世界観を維持する。

必要要素:
- LIFE COMMAND CENTER / RIOT NEON ヘッダー
- 「保存リスト」の大見出し
- 検索
- 絞り込み
- カテゴリ
- 表示モード
- タイトルモード
- 並び替え
- 同期 / 更新

デザイン品質はホームと同等。
保存リストだけ暗く・地味にしない。
アイコン、ネオン枠、手描きグランジ、色の多層感をホーム基準で揃える。

# 10. 実装方式

## 10.1 基本方針
**画像 + HTML/CSS/JavaScript のハイブリッド**

CSSだけでRIOT NEONの絵を再現しない。

### 画像素材に向くもの
- 背景
- ライブ会場
- 人物
- 観客
- ネオンの複雑な質感
- グランジ / 手描き汚し
- ペイント
- 特殊な装飾枠
- ロゴ / 大見出し演出

### HTML/CSS/JSで持つもの
- 可変テキスト
- 日付
- 件数
- 保存リスト内容
- 選択状態
- ソート状態
- フィルター状態
- 検索結果
- 同期状態
- タップ操作
- 画面遷移

原則:
**CSSに絵を描かせない。CSSには絵を配置させる。**

# 12. 空白テンプレートの考え方

変動する内容は画像に焼き込まない。

保存リストで空白化する候補:
- 検索入力文字
- 選択中カテゴリ
- 表示切替状態
- タイトルモード状態
- 並び替え値
- 最終同期時刻
- 件数
- リストタイトル
- 原文プレビュー
- 日付
- その他可変値

固定してよいもの:
- 保存リストの大見出し
- サブコピー
- 背景世界観
- 観客 / ネオン / 都市演出
- UI枠の基本質感
- ナビの基本構造

3. 一覧表示
4. 絞り込み中

---

# 15. iPhone受入条件

最低条件:
- 基準幅 390px で破綻しない
- 文字切れしない
- 横スクロール不要
- 下部ナビが本文を隠さない
- タップ領域は原則44px以上
- 表示切替後も操作しやすい
- 原文モードで長文になっても一覧が破綻しない
- スクロール位置の保持を検討・実装する
- ホームと保存リストで世界観・質感が一致する

---

# 16. 正しい制作順序

今後は必ずこの順で進める。

STEP 1:
機能・情報設計を固定する

STEP 2:
完成見本画像を作る

STEP 3:
状態別の完成画像を作る

STEP 4:
可変領域を空白化したテンプレートを作る

STEP 5:
必要な装飾パーツを切り出す

STEP 6:
座標・サイズ・状態遷移を仕様書化する

STEP 7:
HTML/CSS/JSで実装する

STEP 8:
iPhone基準幅で実機相当確認する

STEP 9:
GitHub Pagesへ公開する

STEP 10:
最新コミットに対する Pages build / deploy が成功したことを確認し、
実際の公開画面まで確認してから「公開反映済み」と報告する

---

# 17. 禁止事項

- 機能を勝手に増やしてスコープを広げない
- 既存UIへCSSを足しただけで「別デザイン」と言わない
- GitHubにコードを書いただけで「公開反映済み」と言わない
- 画像の世界観をCSSだけで安価に再現しようとしない
- 原文を整理版で上書きしない
- 未決定事項をAI判断で確定しない
- 完成画像1枚だけを根拠に、状態遷移を想像で実装しない
